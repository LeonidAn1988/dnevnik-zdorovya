# Дневник здоровья

Давление, сахар и лекарства в одном дневнике. Историю измерений читает
**напрямую из памяти тонометра Omron RS7 Intelli IT** по Bluetooth — без Omron
Connect и без передачи данных куда-либо.
Всё хранится в браузере (IndexedDB).

Прибор держит в памяти **два пользователя по 100 измерений**, и приложение забирает всю
эту историю целиком, а не только последнее значение.

## Назначение и ограничения

Приложение записывает измерения и приём лекарств, хранит их на устройстве и показывает
врачу. **Оно не ставит диагноз, не назначает лечение и не заменяет обращение к врачу.**

Категории давления приведены по шкале ESC/ESH, принятой в клинических рекомендациях, —
это справочная разметка, а не оценка приложения. Сахар оценивается относительно целевых
значений, которые вносит сам человек, обычно со слов врача. При крайних значениях
показываются общие рекомендации — не назначение конкретному человеку.

## Что умеет

- Выгрузка истории с прибора через Web Bluetooth
- Ручной ввод измерений, примечания, отметка руки
- Графики: динамика САД/ДАД со скользящим средним, пульс, разрез по времени суток
- Статистика: средние, разброс, доля в целевом диапазоне, утро против вечера
- Классификация по ESC/ESH и предупреждения о критических значениях
- Печатный отчёт для врача (или сохранение в PDF)
- Экспорт CSV/JSON, импорт CSV, `ubpm.json` и `user1.csv` от omblepy
- Работает офлайн, ставится на домашний экран (PWA)

## Требования

Web Bluetooth есть в **Chrome и Edge** на macOS, Windows, Linux и Android.
**В Safari и в любом браузере на iPhone и iPad Web Bluetooth не поддерживается** — там
остаются ручной ввод, просмотр и импорт файла.

Ещё Web Bluetooth требует защищённый контекст: `localhost` или `https://`. По обычному
`http://<ip>` он просто не включится.

## Запуск

```bash
npm install
npm run dev
```

Откроется `http://localhost:5199`.

Чтобы открыть приложение с телефона в локальной сети:

```bash
npm run dev:lan
```

Адрес будет вида `https://<ip-компьютера>:5199` с самоподписанным сертификатом — браузер
один раз спросит подтверждение. Постоянный адрес удобнее получить деплоем (см. ниже).

### Разрешение Bluetooth на macOS

Chrome должен быть отмечен в **Системные настройки → Конфиденциальность и безопасность →
Bluetooth**. Без этого выбор устройства открывается, но список остаётся пустым.

## Как подключить тонометр

1. Нажмите кнопку Bluetooth на приборе — замигает значок связи. Прибор ждёт подключения
   около минуты, потом гасит радио.
2. В приложении: **Синхронизация → «Подключить и выгрузить»**, выберите прибор в системном
   окне (обычно `BLESmart_…`).
3. Если прибор ответил, что ключ не подходит, значит он ещё не сопряжён с приложением.
   Удерживайте кнопку Bluetooth около двух секунд, пока не замигает `P`, и нажмите
   **«Сопряжение»**. Это делается один раз.

Если сопряжение из браузера не проходит — см. [tools/README.md](tools/README.md):
одна команда в терминале сопрягает прибор, после чего браузер работает сам.

### Что приложение пишет в прибор

Практически ничего. Выгрузка истории — **строго на чтение**. Единственная запись за всё
время работы — разовый ключ сопряжения.

Часы прибора приложение намеренно **не переставляет**: в референсной реализации смещения
этих настроек для HEM-6232T помечены как ненадёжные, а писать наугад в EEPROM тонометра
нельзя. Если часы сбиты, приложение это заметит и скажет — поправить их нужно кнопками на
самом приборе.

## Деплой на GitHub Pages

В репозитории лежит workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml).
После первого пуша в `main` включите Pages: **Settings → Pages → Source: GitHub Actions**.

Приложение соберётся в статику и получит постоянный HTTPS-адрес — этого достаточно, чтобы
пользоваться им с Android. Медицинские данные на сервер не попадают: они остаются в
IndexedDB конкретного браузера.

Учтите обратную сторону: данные **не синхронизируются между устройствами**. Впрочем, для
измерений с прибора это почти не мешает — синхронизация с Mac и с телефона даёт одни и те
же записи с одинаковыми идентификаторами, и они не задваиваются. Расходятся только ручные
записи и примечания; их переносят через экспорт-импорт JSON.

## Разработка

```bash
npm run typecheck    # проверка типов
npm test             # тесты разбора записи и обмена файлами
npm run build        # сборка в dist/
```

Тест разбора записи сверяет результат с эталонными векторами, снятыми с оригинального
Python-драйвера omblepy (`tests/fixtures/omblepy-records.json`). Это самое опасное место
кода: ошибка в битовой раскладке молча исказила бы всю историю измерений.

### Структура

Код разделён на **переносимое ядро** и **платформенные адаптеры**. Ядро не знает ни про
DOM, ни про React: всё, что зависит от среды выполнения, живёт за тремя интерфейсами в
`src/platform/ports.ts` — Bluetooth, хранилище и сохранение файла. Это подготовка к
нативным приложениям: там меняются только реализации адаптеров.

Инвариант проверяется автоматически (`tests/portability.test.mjs`), а не держится на
дисциплине: одного `document.` в удобном месте достаточно, чтобы он сломался незаметно.

| Путь | Что там |
| --- | --- |
| `src/types.ts` | Модель измерений: давление и сахар как размеченное объединение |
| `src/ble/protocol.ts` | Транспорт Omron: 4 канала записи и 4 notify, сборка пакетов, XOR-контроль, разблокировка |
| `src/ble/hem6232t.ts` | Карта памяти прибора и разбор 14-байтовой записи |
| `src/ble/session.ts` | Подключение, сопряжение, выгрузка, диагностика |
| `src/logic/` | Классификация давления и сахара, статистика, экспорт-импорт |
| `src/db/store.ts` | Правила дневника: идентификаторы, дедупликация, настройки |
| **`src/platform/ports.ts`** | **Границы платформы: три интерфейса и реестр** |
| `src/platform/web/` | Реализация под браузер: Web Bluetooth, IndexedDB, скачивание файла |
| `src/ui/` | Интерфейс; графики — рукописный SVG без внешних библиотек |
| `tools/` | Запасной путь через omblepy |
